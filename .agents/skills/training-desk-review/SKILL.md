# Проверка учебного контура

Установи scope review и текущий diff/файлы. Прочитай [обзор](../../../docs/architecture/README.md) и документ затронутой области; используй [матрицу проверок](../../../docs/agents/verification.md).

Проверяй последствия, а не только имена папок:

- Backend: API не обходит logic; DAL не содержит обработчиков входящих HTTP-запросов (исходящий HTTP/JWKS/DNS — внешние DAL-адаптеры), tenant-фильтр и роль не берутся из тела запроса; запись задачи, history и outbox атомарна; конфликт версии не теряет изменение молча.
- Доступ: customer не читает чужое/внутреннее; access JWT проверяет issuer/audience/expiry/client roles и team_slug; public UI не принимает пароль; пароли и токены не попадают в вывод/сборку.
- Settings: JSON durable state не перезаписывается шаблоном, secret values/произвольные ENV refs не выдаются; global restart и callback hot не смешиваются; process-local writer не назван межпроцессным lock.
- Worker: повтор допустим и распознаваем, lease восстанавливается после сбоя, адрес проверяется и закрепляется перед соединением; не обещан exactly-once или общий порядок.
- Контракт: нужная Data Center ветка, настоящий путь/DTO/пагинация, ограничения честно отражены; роли и учебные ID не названы универсальными правилами Jira.
- UI: общий SCSS theme и assets переиспользуются, локальных палитр/копий controls нет, действующий API поддерживает показанные действия.
- Очистка: удалённые модули не остались в scripts/Nx/Docker/документации; runtime JSON, `.env`, данные и тома сохранены; неиспользуемость подтверждена для entrypoints и assets, а не только импортов.
- Setup: существующие `.env` и тома сохраняются, prerequisites проверены, ошибки останавливают выполнение, внешние production-ресурсы не меняются.

Запускай только уместные проверки в разрешённой среде. Новый сложный skill/setup helper можно forward-test в изолированной временной копии, без внешних изменений. Прочитай фактический результат сабагента самостоятельно.

Отчёт: конкретное место, воспроизводимый сценарий и эффект; отдельно результаты проверок и ограничения. Не исправляй незапрошенное в рамках read-only review и не подменяй отсутствие обнаруженных проблем обещанием полной совместимости или production готовности.
