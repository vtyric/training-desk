# Контракт Jira API

Прочитай [поддерживаемое подмножество и отличия](../../../docs/api-compatibility.md). Метаданные официального snapshot: [source.json](../../../docs/vendor/source.json); сам snapshot — [jira-10.3.openapi.json](../../../docs/vendor/jira-10.3.openapi.json). Извлекай только нужные `paths`/`components`, не загружай весь JSON в контекст.

Для затронутого метода установи:

1. Путь и HTTP-метод; в OpenAPI базовый `/rest` задан отдельно в `servers`.
2. Схему запроса/ответа и форматы полей, успешный status code, права и ограничения.
3. Реально поддерживаемые параметры, пагинацию и поведение неизвестных полей.
4. Какие значения — стандарт Jira, какие получены из исследованных форм, а какие являются учебной конфигурацией.

Официальный источник: [JSM 10.3 OpenAPI](https://developer.atlassian.com/server/jira-servicedesk/10.3.swagger.v3.json). Ветка обновляется: корпоративный patch и сохранённая справка могут отличаться. Если snapshot недостаточен, проверь официальный Data Center документ. `pnpm contracts:sync` изменяет snapshot и provenance: запускай при согласованном обновлении контракта, затем просмотри diff. Не выполняй эту запись как побочный шаг обычного setup.

Ключевые границы:

- `/rest/api/2` — версия общего REST API, не версия установленного продукта. Не переходи на Cloud `/rest/api/3`.
- `/rest/servicedeskapi` — request/form/queue/comment API. Customer transitions не являются полным агентским workflow API.
- Тип `10001` и его replacement options — новая учебная конфигурация, не подтверждённая корпоративная форма. Публичный метод/DTO сверяй с Jira отдельно от этих локальных ID.
- Формы `183` и `194` имеют разные обязательные поля. Получай метаданные; не переноси поля одной формы в другую по сходству названия.
- Переход выбирается из ответа transitions. Совпадение transition ID с target status ID в стенде — локальное упрощение.
- Клиентский список заявок не равен очереди агента. Учитывай роль, видимость комментария и tenant-фильтр на сервере.
- Приватный `/rest/servicedesk/1/customer/models` из браузерной записи загружал форму и не доказывает запрос создания заявки.

Если нужная возможность не реализована, добавь её в согласованном объёме либо верни явную ошибку и опиши ограничение. Не принимай неподдерживаемые параметры с фиктивным успехом. Проверяй затронутые DTO/валидацию/права и обновляй compatibility document; backend меняй через соответствующий skill.
