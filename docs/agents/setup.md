# Setup нового репозитория

Сначала откройте [AGENTS.md](../../AGENTS.md) и [setup skill](../../.agents/skills/training-desk-setup/SKILL.md). Репозиторные skills не требуют копирования в home или изменения глобальных support settings.

## План

```sh
node tools/bootstrap.mjs --mode docker
node tools/bootstrap.mjs --mode dev
```

Без `--apply` скрипт показывает план и не запускает Docker, не создаёт ENV и не устанавливает пакеты. Docker выбирают для готового тестового контура; dev — для изменения API/UI на хосте.

## Выполнение установки

Node — из `.nvmrc` и диапазона `package.json`; Docker Engine должен работать, Compose — v2+. Для dev нужен pnpm точной версии `packageManager`.

```sh
node tools/bootstrap.mjs --mode docker --apply
```

Скрипт проверяет prerequisites, готовит отсутствующую ENV, запускает общий PostgreSQL, подготавливает/переносит схему Identity и запускает контур. Пять сервисов: общий PostgreSQL, LDAP, Identity, Service Desk и миграции. Service Desk API и портал — одно приложение; студенческий сервис модерации находится отдельно.

```sh
node tools/bootstrap.mjs --mode dev --apply
```

Dev подготавливает зависимости по lockfile, запускает PostgreSQL/LDAP/Keycloak с ожиданием готовности, применяет миграции и seed. Для рабочих host-процессов затем используйте `pnpm start`. Не меняйте глобальный Node/pnpm/Docker автоматически и не подменяйте package manager или `--frozen-lockfile` ради обхода ошибки.

В обоих режимах `bootstrap --apply` настройка Identity вызывается автоматически. Если запускаете Compose вручную, после готовности Identity выполните `node --env-file=.env tools/configure-identity.mjs` (либо `pnpm identity:configure`). Он настраивает управляемый профиль, sync LDAP и начальные роли; marker защищает последующие пользовательские настройки от повторной записи. Это отдельный bootstrap, не постоянно работающий сервис.

## Git hooks

После установки зависимостей выполните `pnpm hooks:install`. Команда подключает версионируемый [pre-commit](../../.githooks/pre-commit) через локальный `core.hooksPath`; глобальная настройка Git не меняется. Повторный запуск безопасен.

Хук `pnpm precommit` запускает только Prettier (`format:check`) и ESLint (`lint`) для всего рабочего дерева. Файлы и Git index автоматически не изменяются. Для исправления форматирования используйте `pnpm format` и добавьте нужные изменения в index. Это проверка рабочего дерева, а не отдельного снимка staged-файлов; требуются Node/pnpm проекта и установленные зависимости.

## Существующее окружение

`node tools/setup-env.mjs --extend` добавляет только отсутствующие ключи `.env`, сохраняя старые значения. Он не меняет пароли уже существующих БД/LDAP или конфигурацию импортированного realm. Не создавайте новую ENV поверх существующей и не удаляйте тома ради успешного запуска.

`config/backend.json` — шаблон. Рабочий `SETTINGS_FILE` создаётся только при отсутствии; повторный setup его не перезаписывает. Все настройки доступны только администратору службы поддержки через `GET/PUT /api/settings`. Адреса уведомлений применяются без перезапуска, остальные параметры — после перезапуска. Секреты остаются в ENV; [settings](../settings.md).

Конфликт порта требует выбора свободного порта и согласованных issuer/callback URL. Конфликт миграций требует проверки истории, а не редактирования применённых SQL/checksum. Проблема отдельного Docker context/удалённого host не разрешает автоматически управление чужим стендом.

## Проверить результат

`docker compose ps --all`: постоянно работающие сервисы healthy, `migrate` завершился с `0`. Портал: <http://localhost:8080>, Identity: <http://localhost:8081>, Swagger: <http://localhost:8080/docs>. `/health` — проверка работы процесса.

Проверка сценария: вход через Identity, проверка роли, создание обращения `10001`, настройка получателя администратором службы поддержки и проверка доставки на согласованный адрес. Управление браузером и приложениями требует отдельного разрешения. Сквозная проверка создаёт данные; не запускайте её на неизвестном удалённом адресе как read-only health check. Выбирайте проверки по [матрице](verification.md).

Управление users/passwords/roles — в [Identity](../identity.md). Независимые Compose-команды, тома и порты — в [запуск через Docker](../docker.md). Публикация VPS, DNS, корпоративная федерация и выдача внешних доступов не входят в обычный локальный setup.
