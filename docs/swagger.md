# Проверка API Service Desk

Swagger: `http://localhost:8080/docs/` (dev API: `http://localhost:3000/docs/`), OpenAPI: `/docs/json`.

Кнопка **Authorize** запускает вход через Identity, **Try it out → Execute** выполняет запрос. Пароль получает только Identity, Swagger автоматически подставляет токен. Если сессия Identity уже открыта, повторный пароль не нужен. **Logout** очищает авторизацию и завершает общую сессию Identity; перед сменой учётки сначала выйдите.

Авторизация хранится только в памяти страницы. Клиент `service-desk-swagger` использует Code + PKCE S256 без client secret. Уже выданные JWT могут действовать до истечения срока (по умолчанию до пяти минут); после выхода обновление токена не допускается.

## Разделы

- Моя учётная запись: `GET /api/me` показывает пользователя и права.
- Типы обращений: формы и поля.
- Обращения: список со статусами, создание, карточка и переписка.
- Служба поддержки: доступные изменения статуса обращения.
- Настройки службы поддержки: `GET /api/settings`, `PUT` для полной замены и `PATCH` для отдельных полей.

| Действие                             | Заявитель      | Сотрудник поддержки | Администратор службы поддержки |
| ------------------------------------ | -------------- | ------------------- | ------------------------------ |
| Создание обращения                   | Да             | Да                  | Да                             |
| Просмотр и публичные сообщения       | Свои обращения | Свой Service Desk   | Свой Service Desk              |
| Рабочие статусы и внутренние заметки | Нет            | Да                  | Да                             |
| Все настройки `/api/settings`        | Нет            | Нет                 | Да                             |

Методы видны в общем каталоге, права проверяет сервер. Без входа — `401`, без нужных прав — `403`, недоступное обращение может скрываться через `404`.

Готовые учётки: `alice`, `support`, `desk-admin`, `denied`. Это соответственно заявитель, сотрудник поддержки, администратор приложения и пользователь без доступа. `administrator` управляет Keycloak и не заменяет администратора службы поддержки. Назначения и пароли — в [Identity](identity.md), формат JSON — в [настройках](settings.md).

## Настройка и проверка

`pnpm identity:configure` согласует точные callback `/docs/static/oauth2-redirect.html` и post-logout `/docs/` для `DOCKER_BASE_URL` и `API_DOCS_DEV_URL`. Это управляемый клиент документации, не серверная сессия Service Desk.

`pnpm swagger:test` проверяет реальный вход, роли, выход, отказ refresh и silent login после выхода. Создаёт одно обращение и требует локальный запущенный контур. Это HTTP-проверка, не визуальная проверка браузера.

Реализация: [Fastify Swagger UI](https://github.com/fastify/fastify-swagger-ui), [Swagger OAuth2](https://swagger.io/docs/open-source-tools/swagger-ui/usage/oauth2/), [Keycloak OIDC](https://www.keycloak.org/securing-apps/oidc-layers).

В Swagger оставлены только 14 операций: поля формы, список, создание и карточка обращения, переписка, переходы статуса, моя учётная запись и GET/PUT настроек. Вспомогательные health/config скрыты, прежние очереди/поиск/история удалены из API.

Заявитель закрывает своё открытое обращение кнопкой в карточке. Используются существующие GET/POST transitions: доступен только переход закрытия с полями из метаданных. Чужое обращение не закрывается; повторное закрытие — 409. Новых методов нет.

Исполнитель в портале показан без выбора. Новое обращение первоначально назначается единственному активному руководителю поддержки своего Service Desk. Студенты могут переназначать через GET кандидатов и PUT assignee из своего сервиса. При закрытии исполнитель снимается; в том же событии обновления issue.fields.assignee=null. Роль руководителя support-lead наследует права поддержки.

При известном конфликте `different_user_authenticated` страница входа продолжает авторизацию с текущей SSO-сессией. Ошибки пароля и доступа такой переход не обходит. Для намеренной смены пользователя используется Logout.
