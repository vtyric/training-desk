# Портал Artsofte и тема входа

Портал находится в `apps/service-desk/ui`, а страница пароля — в Keycloak `apps/identity/theme`. Они используют общую типографику и семантические стили. Приложение студентов разрабатывается отдельно и подключается к той же форме входа по OIDC.

## Общие библиотеки

| Путь                              | Содержимое                                                                                 |
| --------------------------------- | ------------------------------------------------------------------------------------------ |
| `libs/ui`                         | Готовые PrimeNG-контролы, Aura/blue preset, русский перевод, CDK и native-адаптер Identity |
| `libs/theme/src`                  | SCSS-токены, типографика, поверхности и раскладка Federation                               |
| `libs/theme/assets/brand`         | Шрифты, лицензия и сведения об источниках                                                  |
| `apps/identity/theme/styles.scss` | Сборка общих стилей для Keycloak                                                           |

Feature-компоненты импортируют контролы через `@training-desk/ui`, не напрямую из PrimeNG. Общий provider устанавливается один раз в `main.ts`; SCSS компонентов задаёт раскладку через токены, без копий полей, кнопок и палитр.

Angular использует настоящие PrimeNG-компоненты с Forms/CVA. Keycloak выполняет FTL, поэтому его поля оформляет `libs/ui/src/_identity.scss`. Типографика обоих интерфейсов находится в `_tokens.scss`. Старые глобальные стили нативных контролов выключены для Angular, чтобы не переопределять focus/error PrimeNG.

Подключение библиотек описано в [UI README](../../libs/ui/README.md) и [теме](../../libs/theme/README.md).

## Форма и страницы Keycloak

| Файл темы        | Назначение                                                  |
| ---------------- | ----------------------------------------------------------- |
| `login.ftl`      | Поля входа и сообщение неверного пароля                     |
| `federation.ftl` | Общая оболочка и штатный `authChecker`                      |
| `template.ftl`   | Оформление унаследованных страниц действий Keycloak         |
| `error.ftl`      | Ошибка и безопасное продолжение известного конфликта сессий |
| `messages`       | Русские и английские тексты                                 |

`login.ftl` отправляет `username`, `password` и `credentialId` в `${url.loginAction}`. Проверку пароля через LDAP и сессию ведёт Keycloak. FreeMarker экранирует логин, сообщения проходят `kcSanitize`, пароль не возвращается в `value`.

Контракт шаблонов сверялся с [Keycloak 26.7.0](https://github.com/keycloak/keycloak/blob/26.7.0/themes/src/main/resources/theme/base/login/login.ftl). При обновлении версии требуется проверить FTL-переменные и макросы на реальном Keycloak.

Общая оболочка покрывает вход, ошибку, истёкшую сессию, информационные страницы и подтверждение выхода. Известный `different_user_authenticated` запускает один переход на штатный restart Keycloak с `skip_logout=true`; проверяются origin, путь и auth flow. При недоступном JS остаётся ссылка продолжения. Остальные ошибки не обходятся перенаправлением.

Inter/system-ui, поля 16 px, белая форма и синий геометрический фон задаются общими стилями. На узком экране фон становится верхним блоком. Надписей об учебной среде и тестовых данных нет.

## Сборка темы

`node tools/build-identity-theme.mjs` создаёт `dist/apps/identity/theme/artsofte/login`. Сборщик копирует FTL/JS, компилирует SCSS, переносит шрифты и лицензию в `resources/fonts`, заменяет пути Montserrat на относительные. `stylesVersion` включает хеш CSS и скрипта продолжения, чтобы обновлять кеш ресурсов.

Dockerfile принадлежит `apps/identity`; Nx-зависимости Identity включают `theme` и `ui`. Sass build подтверждает импорты, но не рендер FreeMarker и не внешний вид в браузере. Эти проверки учитываются отдельно; управление браузером требует согласования.

## Вход в портал

`PortalAuth` использует `keycloak-js`, публичный клиент `service-desk-test`, Code + PKCE S256. SDK запускается до роутера и читает `/api/config`. Пароль собирается только в Identity.

Access и refresh tokens остаются в памяти SDK. Перед запросом вызывается `updateToken(30)`, Bearer добавляется только к same-origin `/rest/*` и `/api/*`. При callback восстанавливается разрешённый внутренний путь: `/`, `/requests` или `/requests/HELP-N`. В `sessionStorage` хранится только путь возврата. Logout завершает Identity-сессию и возвращает на `origin + /`.

## Маршруты и состояния портала

| Маршрут          | Назначение                                            |
| ---------------- | ----------------------------------------------------- |
| `/`              | Одна форма: тема, поля из API, отправка без этапов    |
| `/requests`      | Список обращений, статусы и фильтры                   |
| `/requests/:key` | Карточка, исполнитель, переписка и доступное закрытие |
| `/auth/callback` | Клиентский маршрут SDK                                |

Прямое открытие SPA-маршрутов обслуживает Fastify fallback. Бренд — текстовый Artsofte. API ограничивает данные по роли и службе; скрытая кнопка в интерфейсе не заменяет серверную проверку.

Список использует Angular CDK virtual scroll. Строка имеет постоянную высоту 128 px на всех ширинах, `trackBy` и устранение повторов используют `issueId`. Следующие записи автоматически подгружаются порциями по 20 через API `start/limit`, без кнопок страниц. Append сохраняет viewport; устаревший ответ после смены фильтра игнорируется, ошибка дозагрузки оставляет уже показанные данные и ручной повтор.

На странице списка прокручивается только viewport внутри панели. Шапка и фильтр остаются на месте; справа от текста оставлен отступ под системную полосу. Остальные маршруты сохраняют обычную прокрутку. AutoResize PrimeNG Textarea изменяет высоту описания, комментария и JSON-редактора, включая вставку текста.

Исполнитель показан только для чтения. Список кандидатов и выбор исполнителя реализует сервис студентов. Кнопка закрытия появляется только для перехода, возвращённого сервером; ID и обязательные поля берутся из метаданных, после POST карточка перечитывается.

Администратор службы поддержки видит JSON-редактор полного документа через GET/PUT `/api/settings`. Остальные пользователи не меняют настройки. Общий API также поддерживает PATCH; формат — в [настройках](../settings.md).

Подключение внешнего приложения и работа с готовой формой входа описаны в [OIDC-инструкции](../students/02-openid-connect.md).
