# Интерфейс портала и тема входа

Страница входа принадлежит Keycloak. Портал Artsofte входит в приложение Service Desk: Angular-код находится в `apps/service-desk/ui`, сервер — в `apps/service-desk/src`. Приложение студентов разрабатывается отдельно. Портал создаёт и показывает обращения, но не принимает пароль пользователя.

## Файлы и библиотеки

| Путь                                                | Назначение                                                                     |
| --------------------------------------------------- | ------------------------------------------------------------------------------ |
| `apps/identity/theme/artsofte/login/login.ftl`      | Форма Keycloak, стандартные поля входа и ошибки                                |
| `apps/identity/theme/artsofte/login/federation.ftl` | Общая разметка страниц Identity                                                |
| `apps/identity/theme/artsofte/login/template.ftl`   | Оформление унаследованных страниц Keycloak                                     |
| `apps/identity/theme/artsofte/login/messages`       | Русские и английские тексты                                                    |
| `apps/identity/theme/styles.scss`                   | Подключение общей темы и раскладки                                             |
| `libs/ui`                                           | PrimeNG-контролы, тема Aura, русский перевод и адаптер нативных полей Identity |
| `libs/theme/src`                                    | SCSS-токены, типографика, поверхности и раскладка Identity                     |
| `libs/theme/assets/brand`                           | Шрифты, лицензия и сведения об источниках                                      |
| `tools/build-identity-theme.mjs`                    | Сборка ресурсов темы Keycloak                                                  |

SCSS-библиотека зарегистрирована в Nx как `theme`, библиотека готовых контролов — как `ui`. Подключение описано в [общей теме](../../libs/theme/README.md) и [UI-библиотеке](../../libs/ui/README.md). Палитра, кнопки и поля не дублируются в компонентах приложения.

## Форма входа

`login.ftl` отправляет стандартные `username`, `password` и `credentialId` в `${url.loginAction}`. Проверку пароля через LDAP и сессию входа ведёт Keycloak. Шаблон не реализует собственную аутентификацию.

Поля, переменные FTL и `messagesPerField` сверены с [login.ftl Keycloak 26.7.0](https://github.com/keycloak/keycloak/blob/26.7.0/themes/src/main/resources/theme/base/login/login.ftl). FreeMarker экранирует логин, HTML-сообщения проходят `kcSanitize`, пароль не подставляется в `value`. При обновлении Keycloak требуется повторная проверка контракта шаблонов.

Форма использует Inter/system-ui, поля 16 px, широкую кнопку и состояния фокуса и ошибки. Общая типографика находится в `libs/ui/src/_tokens.scss`, адаптер нативных FTL-контролов — в `_identity.scss`. Синий геометрический фон занимает около двух третей экрана, белая форма — правую часть. На узком экране фон превращается в компактный верхний блок. Надписи об учебной среде и тестовых данных отсутствуют.

Раскладка хранится в `libs/theme/src/_federation.scss`. Цвета, размеры и состояния берутся из `--desk-*`; отдельной палитры в приложении нет. Общая разметка покрывает вход, ошибки, истёкшую сессию, информационные сообщения и подтверждение выхода. Штатный `authChecker` Keycloak проверяет сессии в соседних вкладках. Известный конфликт `different_user_authenticated` запускает продолжение входа с текущей SSO-сессией. Для остальных ошибок сохраняется сообщение и безопасный возврат на управляемый `client.baseUrl`; произвольные URL запроса не используются.

## Сборка темы Keycloak

```sh
node tools/build-identity-theme.mjs
```

Сборщик читает `apps/identity/theme`, подключает SCSS из `libs/theme` и `libs/ui`, создаёт `dist/apps/identity/theme/artsofte/login`. Шрифты и лицензия копируются в `resources/fonts`; пути к Montserrat в CSS меняются на `../fonts/*`. URL CSS содержит `stylesVersion` — хеш сборки, который обновляет браузерный кеш после изменения темы.

Dockerfile находится в `apps/identity/Dockerfile`, Compose — в `infra/compose/identity.yaml`. Сборка SCSS подтверждает корректность импортов, но не доказывает отображение FTL на работающем Keycloak. HTTP-проверка и проверка в браузере учитываются отдельно. Управление браузером требует согласования пользователя.

## Портал Artsofte

Портал построен по принципу feature-first. `features/portal` содержит компонент с signals и Reactive Forms, `PortalApi` выполняет HTTP-запросы, `PortalAuth` подключает официальный `keycloak-js`. Зависимости приложения собирает `ui/src/main.ts`.

Маршруты:

- `/` — одна форма создания: тема, все поля и отправка без этапов;
- `/requests` — список со статусами, фильтрами открытых/закрытых обращений и автоматической подгрузкой;
- `/requests/:key` — карточка и переписка;
- `/auth/callback` — возврат SDK после входа.

Шапка содержит текстовый бренд Artsofte и ссылки «Обращения» и «Новое обращение». В карточке исполнитель показан только для просмотра; распределение между сотрудниками реализует отдельный сервис студентов. Заявитель может закрыть своё обращение, если сервер вернул такой переход. После закрытия исполнитель снимается.

Поля формы, обязательность и варианты выбора приходят из API. Значение списка отправляется как `{id: optionId}`. Тип `10001` «Замена оборудования» — конфигурация стенда; формы `183` и `194` доступны отдельно. Успех отображается после ответа сервера. Вложения и участники запросов не показываются; комментарии загружаются первой страницей.

Администратору службы поддержки доступен JSON-редактор всех настроек через `GET/PUT /api/settings`. Сотрудник поддержки обрабатывает обращения, но не меняет настройки сервиса. Видимость элементов в интерфейсе дополняет серверные проверки прав.

## Вход в портал

До запуска Angular Router приложение получает `GET /api/config` и инициализирует SDK: `onLoad: login-required`, Authorization Code, `pkceMethod: S256`, `checkLoginIframe: false`. Callback — `origin + /auth/callback`. После обработки SDK URL очищается, а разрешённый внутренний путь восстанавливается. В sessionStorage сохраняется только путь `/`, `/requests` или карточки; токены туда не записываются.

Access/refresh tokens остаются в памяти SDK. HTTP-перехватчик обновляет токен через `updateToken(30)` и добавляет Bearer только к предусмотренным API своего origin. Пароли и токены не отправляются в сторонние адреса. Выход вызывает SDK logout с возвратом на `origin + /`. Поведение основано на [документации JS adapter](https://www.keycloak.org/securing-apps/javascript-adapter).

## Подключение общей темы

Angular использует готовые PrimeNG/Aura-контролы через `@training-desk/ui`, а не прямые импорты PrimeNG в компонентах. Общий provider темы и русского перевода подключается один раз. `theme.install($native-controls: false)` отключает старые стили нативных полей, чтобы они не перекрывали PrimeNG; `ui.install()` связывает переменные раскладки с семантическими токенами дизайн-системы.

Keycloak использует нативные FTL-контролы через адаптер общей UI-библиотеки. Angular-компоненты на его странице не запускаются. Общие параметры добавляются в библиотеку, уникальная геометрия — в отдельный SCSS-mixin. Шрифты и лицензии передаются сборщиком потребителя. Тема определяет внешний вид, права доступа проверяет сервер.

Источники материалов записаны в [sources.json](../../libs/theme/assets/brand/sources.json). Изображения Abanking, `artsofte.svg` и `favicon.svg` удалены; текстовый бренд не требует этих файлов.

Список обращений использует Angular CDK virtual scroll через общую библиотеку UI. В DOM находятся видимые строки и небольшой буфер. Высота строки одинакова на всех размерах экрана. Список занимает оставшуюся высоту экрана и прокручивается одной полосой у правого края панели; текст защищён от перекрытия полосой. Следующие обращения подгружаются порциями по 20 при прокрутке, без кнопок страниц; API сохраняет start/limit.

`trackBy` виртуального списка и устранение повторов используют стабильный `issueId` обращения, поэтому уже загруженные строки сохраняются при добавлении следующей порции.

Описание обращения, комментарии и JSON-редактор используют штатный autoResize директивы PrimeNG Textarea: высота меняется по содержимому, включая вставку из буфера.
