# Принятые решения и происхождение

Здесь зафиксирована итоговая архитектура. Корпоративный трафик — источник наблюдений, а не автоматическое требование воспроизвести внутренние системы. Пароли, личные данные сотрудников и журналы входа не переносятся.

| Решение                                                                          | Статус и причина                                                                                                                                              |
| -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Identity и Service Desk — независимые приложения                                 | Оба предоставляют внешние интеграции приложению студентов                                                                                                     |
| Студенческий клиентский интерфейс и сервер — в отдельном репозитории             | Внешнее приложение модерации отдельно; прежний клиентский интерфейс — наш тестовый портал, встроен в `apps/service-desk/ui`, а не отдельное Nx-приложение     |
| Identity на Keycloak со схемой `identity` в общей БД и LDAP federation с записью | Пользователи, пароли и атрибут команды управляются через Keycloak Admin Console; пользователи/пароли сохраняются в LDAP                                       |
| Роли доступа принадлежат Keycloak                                                | Client roles `service-desk:customer/support/admin`, а также composite-роль `support-lead`; LDAP-группы не определяют допуск в API                             |
| Приложение студентов — публичный OIDC-клиент                                     | `student-service`, Authorization Code + PKCE S256, зарегистрированный callback; password/direct grant отключён                                                |
| Service Desk — сервер API с проверкой JWT                                        | Проверяет access token через `jose`/JWKS, issuer, audience и роли клиента; не обменивает code, не принимает пароль и не выдаёт cookie                         |
| Сессия входа принадлежит Identity                                                | Входом и выходом управляет Identity; Service Desk не создаёт cookie-сессию. Для каталога сотрудников используется отдельный серверный секрет с правами чтения |
| Статические API-токены сохранены для совместимости                               | Agent/customer bearer и bootstrap `ADMIN_TOKEN` дополняют JWT, но не заменяют управление учётными записями Identity                                           |
| Самостоятельные тестовые пользователи                                            | У студентов нет корпоративных доступов; работа стенда не зависит от корпоративных Jira, LDAP или ADFS                                                         |
| Корпоративный вход отделён от учебного решения                                   | Наблюдался OIDC через ADFS, но не доказан прямой LDAP. Учебный Keycloak не служит копией корпоративного провайдера                                            |
| Jira Data Center 10.3                                                            | Корпоративная сборка `10.3.16-QR-0016`; снимок официальной спецификации `10.3.27`, источник в `docs/vendor/source.json`                                       |
| Только выбранное публичное подмножество API                                      | Полной совместимости Jira, Cloud `/rest/api/3` и приватных browser endpoints нет                                                                              |
| Формы 183 и 194 различаются                                                      | Поля «Не запускается ПК» и «Не получается авторизоваться» не взаимозаменяемы                                                                                  |
| Тип 10001 — учебная замена оборудования                                          | Новые type/option IDs не заявляются как подтверждённая корпоративная форма                                                                                    |
| Workflow — учебная модель                                                        | Полная production-схема и transition IDs не получены; совпадение transition ID с target status ID — локальное упрощение                                       |
| Outbox атомарен с обращением и историей                                          | Отправка webhook выполняется отдельно; ответ `201` не доказывает доставку                                                                                     |
| Webhook и список обращений дополняют друг друга                                  | Подписка даёт уведомления, список с пагинацией помогает сверить пропущенные события                                                                           |
| Fastify, pnpm, Nx, Drizzle, PostgreSQL и три слоя                                | Согласованный стек, `api → logic → dal`; локальный `a-spec` был образцом, не источником секретов                                                              |
| RxJS по потребности                                                              | Не заменяет последовательные `async/await` и транзакции без необходимости                                                                                     |
| Пять Compose-сервисов                                                            | Общие PostgreSQL и LDAP, Identity, миграции и Service Desk с порталом/API. Подготовка окружения — отдельный инструмент                                        |
| Тема Identity Artsofte Federation                                                | FTL/CSS по предоставленному образцу; общая SCSS-библиотека находится в `libs/theme`                                                                           |
| Репозиторные skills и AGENTS                                                     | Направляют последующих агентов к текущей архитектуре, контрактам и безопасному setup                                                                          |

## Постоянные настройки

`config/backend.json` служит шаблоном; рабочий `SETTINGS_FILE` не перезаписывается при повторном запуске. Основной источник адресов уведомлений — JSON, обработчик переносит нужные данные в SQL. Адрес уведомлений применяется без перезапуска; остальные параметры — после перезапуска. JSON-параметры, связанные с секретами, содержат только фиксированные имена переменных окружения. `security.allowLegacyApiTokens=false` по умолчанию, bootstrap `ADMIN_TOKEN` сохраняется.

## Планы не равны поставленным функциям

Автоматическое согласование Identity-пользователей с API-командами, массовая генерация/сброс, внешние backup и production TLS/deploy остаются отдельными задачами. Наличие Docker-конфигурации не означает публикацию на VPS. Outbox-событие без зарегистрированного доступного получателя не подтверждает доставку webhook.

## Как менять решение

Изменение объёма и внешнего контракта согласуется с пользователем. После реализации обновляются документы и skills. Для Jira приводится источник Data Center нужной ветки, корпоративное наблюдение отделяется от учебного правила. Применённые SQL-миграции остаются неизменными.
