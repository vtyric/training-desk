# Подключение приложения студентов

Keycloak и Service Desk уже работают на сервере. Команда запускает у себя только своё приложение: сначала на localhost, затем на собственном стенде. Исходники и Docker-контейнеры серверного контура для подключения не нужны. Язык и фреймворк приложения можно выбрать самостоятельно.

## Адреса и доступы

| Что открыть                           | Адрес                                                                                       | Учётка                                                     |
| ------------------------------------- | ------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| Пользователи, роли и клиенты Keycloak | [Консоль управления](https://auth.makar-star.space/admin/master/console/#/training/users)   | `administrator`; пароль выдаётся отдельно                  |
| Портал заявителя                      | [Service Desk](https://desk.makar-star.space/)                                              | `alice`, `support`, `support-lead` или `desk-admin`        |
| Вызовы API и настройки                | [Swagger](https://desk.makar-star.space/docs/)                                              | `desk-admin` для настроек, остальные — для своих сценариев |
| Описание OpenID Connect               | [Discovery](https://auth.makar-star.space/realms/training/.well-known/openid-configuration) | Вход не требуется                                          |

Пароли и ключ подписи webhook команда получает отдельно. Пароль администратора Keycloak не подходит для входа в Service Desk. Серверная `.env` и мастер-ключ подписи для работы команды не нужны.

## Порядок работы

1. [Keycloak: пользователи, роли и доступ только администраторам](students/01-keycloak-and-roles.md). Результат: учётка связана со службой `demo`, ей назначены права внешнего API и собственного приложения.
2. [OpenID Connect: вход из localhost и со своего стенда](students/02-openid-connect.md). Результат: готовая форма Artsofte возвращает пользователя в приложение, backend проверяет access token и роль.
3. [Service Desk: Swagger, proxy, webhook и обработка обращения](students/03-service-desk.md). Результат: новое обращение приходит в приложение команды, а назначение, переписка и статусы сохраняются через API.

В примерах frontend работает на `http://localhost:4300`, backend — на `http://localhost:3000`. `https://team1.example.ru` обозначает будущий адрес приложения команды; его нужно заменить своим. Адреса `auth.makar-star.space` и `desk.makar-star.space` менять не требуется.

В общей службе `demo` один получатель webhook. Несколько команд, работающих с ней одновременно, меняют один адрес. Перед настройкой получателя команды согласуют очередь работы либо получают отдельную службу/стенд у владельца.

Фактические результаты и границы проверки описаны в [отчёте интеграции](students/integration-verification.md).
