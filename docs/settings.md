# Настройки Service Desk

Все параметры хранятся в одном JSON-документе. Для работы с ним есть три метода, доступных администратору службы поддержки:

| Метод                 | Назначение                        |
| --------------------- | --------------------------------- |
| `GET /api/settings`   | Получить весь JSON настроек       |
| `PUT /api/settings`   | Сохранить изменённый JSON целиком |
| `PATCH /api/settings` | Изменить отдельные поля           |

GET возвращает сам документ, без обёртки `config`. PUT принимает такой же документ и возвращает сохранённую версию с увеличенным `revision`. Успешный ответ — `200`. Заявитель и сотрудник поддержки получают `403`, без входа — `401`.

В Swagger войдите как `desk-admin`, выполните GET, скопируйте JSON в PUT и измените нужные значения. В портале администратору доступен тот же JSON-редактор. Пользователями и назначением прав управляйте в Keycloak.

## Содержимое JSON

- `server`: адрес, порт, ограничение тела HTTP-запроса.
- `database`: размер пула и имя переменной подключения.
- `identity`: проверка токенов, адреса Identity и каталог сотрудников (`directoryClientId`, фиксированное имя ENV секрета `directoryClientSecretEnv`, `directoryTimeoutMs`). Секрет не входит в JSON.
- `service`: название Service Desk, ключ проекта и идентификатор портала.
- `webhooks`: интервалы отправки уведомлений, таймаут и повторы.
- `ui`: параметры портала и входа.
- `security`: совместимость со статическими токенами; штатный вход через Identity.
- `teams`: адреса получения уведомлений об обращениях. Ключ — идентификатор Service Desk из `GET /api/me` (`teamId`).
- `version`, `revision`: версия структуры и номер сохранённой редакции.

Например, запись получателя в `teams`:

```json
{
    "00000000-0000-4000-8000-000000000001": {
        "webhook": {
            "id": "00000000-0000-4000-8000-000000000001",
            "url": "https://example.com/webhooks/service-desk",
            "enabled": true,
            "createdAt": "2026-01-01T00:00:00.000Z"
        }
    }
}
```

Это фрагмент поля `teams`, а не полное тело PUT. Используйте настоящий `teamId`, верните остальные поля GET без удаления. `id` совпадает с ключом; время создания существующей записи сохраняется сервером. Адрес должен быть публичным HTTPS; внутренние адреса и перенаправления запрещены. Удаление записи из JSON отключает её получателя; история доставок сохраняется.

## Применение и конфликты

Адреса уведомлений применяются без перезапуска на следующем цикле обработки. Уже начатая отправка может использовать прежний адрес. Остальные параметры активируются после перезапуска Service Desk. Заголовок `X-Restart-Required: true` сообщает о необходимости перезапуска; поле не добавляется в JSON.

Сохраняйте `revision`, полученный GET. Можно также передать `If-Match` со значением ETag. Если другой администратор уже изменил документ, PUT вернёт `409`; загрузите актуальную версию. Если If-Match и revision тела различаются — `400`.

## Хранение

`config/backend.json` — шаблон. Рабочий JSON задаёт `SETTINGS_FILE`: по умолчанию `.local/settings/backend.json`, в Docker — `/data/settings/backend.json` на постоянном томе. Шаблон копируется только при отсутствии файла. Сохранение атомарное, файл имеет права `0600`; один процесс последовательно обрабатывает записи. Межпроцессной блокировки нет.

Пароли, ключи подписи и значения переменных окружения через API не выдаются и в JSON не записываются. Допустимые ссылки на ENV фиксированы; произвольные ссылки, например на административный пароль, не принимаются.

Отдельных API команд, статических токенов, подписок или «глобальных/командных настроек» нет. Вся конфигурация меняется через эти методы; существующие обращения и учётные записи не удаляются при обновлении конфигурации.

## Изменение одного поля

`PATCH /api/settings` принимает только изменяемую часть JSON:

```json
{
    "server": {
        "port": 3001
    }
}
```

Остальные поля сохраняются. Вложенные объекты объединяются, массив заменяется целиком. Например, для адреса уведомлений достаточно передать `teams` → нужный идентификатор → `webhook` → `url`; `enabled` и время создания сохранятся. Новая запись получателя должна содержать все обязательные поля.

`null` не удаляет поля и не принимается. Для удаления получателя остаётся полная замена JSON через PUT. Поля `version` и `revision` через PATCH не меняются: редакцию увеличивает сервер. Необязательный `If-Match` из GET защищает от записи поверх чужих изменений; устаревшая редакция возвращает 409. Неизвестное поле или недопустимое значение возвращает 400 без изменения файла.

Права, проверка HTTPS-адреса, атомарное сохранение и правила перезапуска такие же, как у PUT. Ответ 200 содержит весь JSON после изменения, ETag и X-Restart-Required.
